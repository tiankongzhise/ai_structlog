## 二、P0 级别问题（必须立即修复）

### 2.1 标准logging桥接功能不可用

| 属性 | 内容 |
|------|------|
| **严重程度** | 阻断级 |
| **审计来源** | big-pickle (P0-1)、hy3 (P0)、minima2.5 (P1) |
| **涉及文件** | `src/tkzs_structlog/core/initializer.py:90-166` |
| **需求依据** | 开发需求.md 第119行 — "bridge_std_logging=True 时调用 structlog.stdlib.recreate_defaults()" |
| **现状** | 代码未调用 `recreate_defaults()`，导致 `logging.getLogger().info()` 无输出处理器 |
| **测试证据** | `tests/integration/test_stdlib_bridge.py::TestStdlibBridge::test_stdlib_logging_emits_message` 失败 |
| **影响** | 核心集成功能不可用，测试直接失败 |

**修复方案**: 在 `_setup_processors` 中 bridge=True 分支末尾添加 `structlog.stdlib.recreate_defaults(...)` 调用，或将 ConsoleRenderer 配置为 `ProcessorFormatter` 并添加到根日志器处理器。

### 2.2 PGSQL批量写入日志计数Bug

| 属性 | 内容 |
|------|------|
| **严重程度** | 高 |
| **审计来源** | big-pickle (P0-2) |
| **涉及文件** | `src/tkzs_structlog/extensions/pgsql_handler.py:210-213` |
| **问题代码** | `self._batch.clear()` 先执行后，`len(self._batch)` 永远为0 |
| **对比** | `redis_handler.py:168-171` 同逻辑正确实现 |
| **修复方案** | 将日志输出语句移到 `clear()` 之前，或先保存 `batch_size` |
